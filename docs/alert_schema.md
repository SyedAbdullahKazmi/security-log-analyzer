# Alert Schema
## Security Log Analyzer and Automated Alert System

### 1. Purpose

The Alert Schema defines the standard structure of alerts generated by the detection engine.

Each alert will contain enough information for a security analyst to understand what happened and why the system identified the activity as suspicious.

### 2. Alert Fields

| Field | Data Type | Description |
|---|---|---|
| alert_id | String | Unique identifier for the alert |
| timestamp | ISO 8601 string | Time when the alert was generated |
| rule_id | String | Detection rule identifier, such as R1 |
| rule_name | String | Name of the detection rule |
event_category | String	| Identifies whether the alert originated from SecurityLog or FileIntegrity
| severity | String | Low, Medium, High, or Critical |
| computer | String | Computer associated with the event |
| affected_entity | String | User account, computer, or other affected entity |
| source_ip | String or null | Related source IP address, if available |
| reason | String | Explanation of why the rule triggered |
| evidence | Array | Supporting event records or event references |

### 3. Example Alert

```json
{
  "alert_id": "ALT-0001",
  "timestamp": "2026-11-18T10:04:00",
  "rule_id": "R1",
  "rule_name": "Repeated Failed Login Attempts",
  "event_category": "SecurityLog",
  "severity": "Medium",
  "computer": "LAB-PC",
  "affected_entity": "test_user",
  "source_ip": "198.51.100.20",
  "reason": "Five failed login attempts occurred within five minutes.",
  "evidence": [
    "Five related Event ID 4625 records",
    "Time window: 10:00 to 10:04"
  ]
}

{
  "alert_id": "ALT-FIM-0001",
  "timestamp": "2026-11-18T14:30:00",
  "rule_id": "FIM-01",
  "rule_name": "Monitored File Modified",
  "event_category": "FileIntegrity",
  "severity": "Medium",
  "computer": "LAB-PC-02",
  "affected_entity": "C:\\Important\\test_file.txt",
  "reason": "File SHA-256 hash differs from the approved baseline.",
  "evidence": {
    "previous_sha256": "<baseline_hash>",
    "current_sha256": "<current_hash>"
  }
}
```

### 4. Severity Levels

- Low: Activity requiring basic review.
- Medium: Suspicious activity that should be investigated.
- High: Activity that may indicate a significant security risk.
- Critical: Very serious activity requiring urgent investigation.

### 5. Alert Storage

Alerts will be stored persistently using a supported format such as CSV, JSON, or SQLite.

The system will preserve the rule information and supporting evidence so that analysts can review and investigate generated alerts.

### 6. Multi-Computer Support

Each alert will identify the originating computer. For registered agents, the system may also include a unique device identifier to distinguish computers with similar names.
